Uforiya
Every track. Every version. Every collaborator. Nothing lost.

Right now, Uforiya is a workspace for unreleased music. A song keeps every version, its stems and everyone working on it in one place, instead of a folder full of files named final_v3_REALFINAL. Producers, artists, songwriters, mix engineers and studios work on the same track from anywhere, with feedback pinned to the exact second it's about.

Where it's going

I'm building Uforiya into a full creative ecosystem: software that helps musicians make music and improves the creative process from the first idea to the final master. The workspace is the foundation. The audio tools, the Sample Organizer and the VST I'm building now are the next pieces.

What it does today
  • Detects BPM, key and duration on upload
  • Keeps every version of a track, with its stems
  • Collaborator roles and credits
  • Comments pinned to the exact second
  • Private sessions for studio days and camps
  • Seven browser-based audio tools

How it's built

I built Uforiya solo, foundation first: data model, permissions and file security before a single screen. The audio pipeline sits on top of that.

  • Next.js and React (TypeScript) for the app
  • Python / FastAPI worker for BPM and key analysis
  • Browser-side audio processing for the tools
  • Supabase and PostgreSQL for accounts, roles and data
  • Cloudflare R2 for audio storage, Stripe for Pro
Read: Foundation First

In the studio

Uforiya is used in real rooms, not just in demos. I've worked with studios across Toronto, most notably Main One, who use Uforiya to run their camps: every artist, producer, writer and engineer uploads to one private session, and nothing gets lost between rooms.

  • Private sessions built around how camps actually run
  • Feature work shaped directly by studio feedback
  • Built in the open with the producers using it
